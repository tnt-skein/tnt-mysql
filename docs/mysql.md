# MySQL

`tnt-mysql` — драйвер MySQL для Tarantool: фасад над официальным
неблокирующим роком `mysql`. Соединения живут в пуле, срок один на вызов,
отказ — пара `nil, err` с родом по errno сервера, а транзакция держится
на одном соединении.

```lua
local mysql = require('tnt.mysql')

local db = mysql.new({ host = 'db', user = 'app', password = secret, db = 'app', pool = { size = 4 } })

local rows, err = db:query('select id, name from users where votes > ?', { n = 1, 100 })
local done, err = db:execute('insert into users (name) values (?)', { n = 1, 'Анна' })   -- done.last_id — новый ключ
```

Отказ — пара `nil, err`, где `err` — отказ `tnt-storage` с родом,
признаком отправки и приговором повтору. Исключение — ошибка
программиста: негодный аргумент, незнакомая настройка, значение, которое
нельзя передать, `tls` без корня, настройка, которой не знает рок без
заплаты 0011.

Зависимости: [`tnt-must`](https://github.com/tnt-skein/tnt-must)
(бросок отказа рока как есть), [`tnt-log`](https://github.com/tnt-skein/tnt-log)
(журнал), [`tnt-pool`](https://github.com/tnt-skein/tnt-pool)
(соединения), [`tnt-retry`](https://github.com/tnt-skein/tnt-retry)
(повторы), [`tnt-sql`](https://github.com/tnt-skein/tnt-sql) (диалект
`mysql` для построителя запросов) и
[`tnt-storage`](https://github.com/tnt-skein/tnt-storage) (срок, отказ
с родом, значения и драйвер SQL над роком). Рок `mysql` — форк
с починками, он ставится отдельно (ниже, «Рок: форк с починками»).

## Зачем пакет

У Tarantool есть официальный рок `mysql`: неблокирующий, живущий
с файберами. Писать протокол MySQL заново значило бы потратить недели
и получить худший ввод-вывод, поэтому пакет — **фасад над роком**, а не
свой протокол. Рок при этом не знает срока, отказывает исключением-строкой
и в нескольких местах молча портит выдачу; форк чинит выдачу, а фасад
приводит рок к договору драйверов `tnt-storage`:

- пул — [`tnt-pool`](https://github.com/tnt-skein/tnt-pool/blob/main/docs/pool.md),
  который драйвер заводит сам, с проверкой живости и сбросом без сети;
- отказ, срок и кодирование значений —
  [`tnt-storage`](https://github.com/tnt-skein/tnt-storage/blob/main/docs/storage.md):
  отказ `TntStorageFailure` с родом, один миг срока на вызов с ожиданием
  рока в работнике, правило «чем передать `int64`»;
- повторы — [`tnt-retry`](https://github.com/tnt-skein/tnt-retry/blob/main/docs/retry.md)
  по полю `retriable` отказа;
- вход — пара «текст и параметры» от
  [`tnt-sql`](https://github.com/tnt-skein/tnt-sql/blob/main/docs/sql.md),
  диалект драйвера — его правила.

Пул, срок, повторы, транзакции и решение, вернуть соединение или
выбросить, — общий драйвер SQL над роком из `tnt-storage`
(`tnt.storage.driver`, раздел «Драйвер SQL над роком» его документа).
Своё у пакета — настройки и знание рока:

| Слой | Модуль | Что делает |
|---|---|---|
| настройки | `tnt.mysql.settings` | умолчания, проверка, шифрование с корнем и ключ сервера, потолок выборки на сервере |
| знание рока | `tnt.mysql.rock` | вход аргументами, шифрование и ключ сервера, отказ на роке без них, потолок `max_execution_time`, живость по `quote('')`, errno из отказа, слово вместо ответа о пароле, число строк и новый ключ |
| драйвер | `tnt.mysql` | диалект `mysql` и сборка драйвера над роком |

Чего здесь нет:

- **TLS без сверки сертификата** — ниже, «Шифрование и ключ сервера».
- **Курсора** — большие выборки берут постранично по ключу.
- **Нескольких операторов в одном вызове**.
- **Точек сохранения** и вложенных транзакций.
- **Адреса строкой** и сокета Unix — только `host` и `port`.

## Как пользоваться

Примеры в этом документе прогнаны на MySQL 8.4 стенда с настройками
по умолчанию, сертификатом и ключом RSA стенда (`make mysql-up`,
`test/stand/mysql.sh`) с форком рока (`make deps-mysql`); вывод — как
напечатал прогон.

### Рок: форк с починками

Рок — не выпуск и не закреплённый `master`, а форк. Выпуск `2.1.3`
на Tarantool 3.8 не собирается вовсе, `master` (`b88dbb8`) собирается
только CMake 3 с ослабленными ошибками clang, входит только через
`mysql_native_password` и не чинит ни одной из ошибок ниже. Форк — это
`tarantool/mysql` на `b88dbb8` и одиннадцать заплат из `rocks/mysql/` поверх.
Девятая меняет вложенный коннектор: вместо `tarantool/mariadb-connector-c`
`54cdb25` (MariaDB Connector/C 3.0.2) — выпуск 3.4.10 у источника
(`mariadb-corporation/mariadb-connector-c` `8153da4`), и только в нём есть
вход `caching_sha2_password` (ниже, «Сервер»).

| Заплата | Что чинит |
|---|---|
| `0001-driver-include-string.h-for-strcmp.patch` | ошибка clang 16: `strcmp` без заголовка |
| `0002-driver-keep-the-column-type-after-a-NULL-value.patch` | после первого NULL столбец терял значения во всех следующих строках |
| `0003-driver-read-BIGINT-UNSIGNED-above-2-63-1-exactly.patch` | `BIGINT UNSIGNED` больше 2⁶³−1 читается точно |
| `0004-driver-report-the-error-number-affected-rows-and-ins.patch` | отказ — `box.error` типа `MySQLError` с полем `mysql_errno`; `execute` отдаёт число строк и новый ключ |
| `0005-driver-report-the-error-of-a-later-statement.patch` | отказ второго оператора не теряется |
| `0006-driver-fetch-prepared-values-longer-than-the-column-.patch` | подготовленный путь не обрывает выдачу; отказ выборки — отказ |
| `0007-driver-refuse-a-statement-with-fewer-values-than-par.patch` | недостающий параметр — отказ `2031`, а не значение со стека рока |
| `0008-driver-read-a-number-of-a-column-within-the-length-o.patch` | число подготовленного пути читается в пределах своей длины: `200` в буфере на три байта приходило `2003`, а `false` столбца `boolean` — числом от 1 до 9 |
| `0009-connector-log-in-with-caching_sha2_password-of-Maria.patch` | коннектор 3.4.10 с `caching_sha2_password`, вшитым в рок; выросшие буферы подготовленного пути привязываются заново после чтения строки — в 3.4 привязка обнуляет длину строкового значения |
| `0010-driver-keep-the-symbols-of-the-connector-inside-the-.patch` | символы коннектора и его zlib остаются внутри драйвера: отданные наружу, они перехватывали вызовы системной zlib, и gzip любого модуля процесса мог его уронить |
| `0011-driver-connect-with-verified-TLS-and-a-pinned-server.patch` | `connect` берёт TLS со сверкой сертификата сервера по корню и файл открытого ключа RSA сервера; нечитаемый файл ключа — отказ до входа; поле `features` отличает рок, который их берёт, от прежнего |

Всё, что прежде чинили заплаты к старому коннектору, в 3.4.10 уже есть:
сборка на CMake 4 и свежем clang, тип крюка ожидания ввода-вывода
(`MARIADB_OPT_IO_WAIT`, через него рок уступает файберам), дочитывание
обрезанного значения `mysql_stmt_fetch_column`.

Десятая заплата — о сборке драйвера. Коннектор вшит в него вместе
со своей zlib, а системная libz приходит в процесс вместе с драйвером,
когда её тянет libcrypto (так на Debian 13), и свои символы ищет
сначала в нём. Драйвер без заплаты отдавал символы вшитой zlib наружу,
и они перехватывали внутренние вызовы системной: поток gzip любого
модуля процесса — сжатие ответов, выгрузка трасс, — заведённый через
`ffi.load('z')`, шёл по двум zlib разом. При разных версиях это
падение: с роком на коннекторе 3.0.2 (zlib 1.2.5) процесс на Debian 13
(zlib 1.3.1) падал сигналом SIGSEGV в первом же `deflateInit2_`.
У коннектора 3.4.10 zlib тоже 1.3.1, и на Debian 13 версии совпадают
случайно. С заплатой драйвер отдаёт наружу только свои функции
(`luaopen_mysql_driver` и ещё две из `driver.c`), а системная zlib
зовёт саму себя. Прячет символы компоновщик Linux
(`--exclude-libs,ALL`); на macOS библиотека зовёт свои функции
напрямую, и перехвата там нет.

Одиннадцатая заплата — о шифровании. Коннектор 3.4.10 собран
с OpenSSL и умеет и TLS, и ключ сервера из файла, а рок без заплаты
передаёт ему только узел, учётную запись, пароль и базу и прочие ключи
пропускает молча. С заплатой `connect` берёт `ssl = { ca, cert, key }` —
TLS, где сертификат сервера сверяется всегда, — и `server_public_key`
(ниже, «Шифрование и ключ сервера»). Прежний рок о них не знает и вошёл
бы открытым текстом, поэтому фасад спрашивает поле `features` рока
и без него отказывает при заведении драйвера.

Ставится целью `make deps-mysql` (`tools/deps_mysql.sh`): клон
`tarantool/mysql`, коммит, заплаты рока, подмодуль на коммите из заплаты
0009, `tt rocks make` в `.rocks` проекта. Заплаты накладываются
с индексом: коммит подмодуля — часть заплаты, а без индекса `git apply`
его молча пропускает. Нужны CMake, компилятор и заголовки OpenSSL
(`libssl-dev`); коннектор вложен в рок и с машины не берётся. В `make deps`
цель не входит: гейты от рока не зависят, а живые проверки без него
пропускаются. Сборка оставляет отпечаток рецепта — коммит и заплаты —
в `.rocks/mysql-fork.sha256`, и живые проверки сверяют его с деревом: рок,
собранный до новой заплаты, остаётся в `.rocks`, пока его не пересоберут,
и на нём проверки пропускаются с подсказкой «пересоберите: make
deps-mysql», а не падают на том, что заплата чинит. Сверка идёт
до загрузки: такой рок в процесс проверок не попадает вовсе, и драйвер
без заплаты 0010 не уронит gzip соседнего набора того же прогона.
Пропуск молчит — прогон зелёный, а форк на сервере никто не проверил, —
поэтому догнать рецепт можно и не помня, отстал ли рок:
`tools/deps_mysql.sh --if-stale` пересобирает рок, только если он стоит
в `.rocks`, а отпечаток не сходится с рецептом, а рока, которого нет,
не ставит — цель в `make deps` не входит нарочно.
В rockspec пакета рок не объявлен нарочно — иначе установка взялась бы
собирать выпуск `2.1.3` и упала бы; рок подключается по имени, как
внешняя зависимость, а `mysql.new` на узле без рока бросает сразу:

```lua
mysql.new({ user = 'app', db = 'app' })
--> исключение: рок mysql не установлен (module 'mysql' not found:): поставьте форк с починками — make deps-mysql, docs/mysql.md
```

На роке без починок фасад работает тоже, только хуже: род отказа — по
английским словам (`server_code` пуст), `affected` и `last_id` — пусто,
вход — только через `mysql_native_password`, а ошибки, которые чинит
форк, остаются: выборка после NULL, выдача подготовленного пути и числа
на нём молча портятся.

Заплаты написаны в формате `git format-patch`, по одной починке на заплату
и с объяснением в сообщении: они же — готовые правки для самого рока.
Подъём закреплённого коммита — отдельная правка со сверкой живыми
проверками заново: `master`, ушедший вперёд, либо не примет заплат, либо
молча поменяет поведение, которое проверки сверили.

**Сервер — MySQL 8.4 или 9, вход — `caching_sha2_password`.** Так
MySQL 8.4 и 9 входят по умолчанию, а `mysql_native_password` в 8.4
выключен и в MySQL 9 убран. Учётку, заведённую `mysql_native_password`
на сервере, который его ещё держит, рок тоже впускает — сервер сам
переключает способ. Плагин `caching_sha2_password` вшит в рок, а не
ищется в каталоге плагинов коннектора, которого у рока нет; SHA-256
и RSA ему даёт OpenSSL.

Сервер помнит хеш пароля учётки после первого входа, и следующие входы
короткие. Полный вход — первый после подъёма сервера, смены пароля или
`FLUSH PRIVILEGES` — без TLS идёт обменом ключом: коннектор шифрует
пароль открытым ключом RSA сервера. Без настроек **ключ приходит
по тому же открытому соединению**, и посредник в сети, подменивший
его, прочтёт пароль. Против него — `tls` либо закреплённый файлом ключ
`server_public_key` (ниже, «Шифрование и ключ сервера»).

### Драйвер: `mysql.new`

```lua
local mysql = require('tnt.mysql')
local sql = require('tnt.sql')

local db = mysql.new({
    host = '127.0.0.1',
    port = 13306,
    user = 'app',
    password = "app'se\\cret",   -- кавычка и обратная черта — нарочно
    db = 'app',
    timeout = 2,                 -- срок вызова по умолчанию
    pool = { size = 4 },
})

db:execute('create table users (id bigint auto_increment primary key, name varchar(50), votes int, meta json)')
--> { affected = 0, last_id = 0 }

local users = sql.table('users', { 'id', 'name', 'votes', 'meta' })

db:execute(users:insert({ { name = 'Анна', votes = 120 }, { name = 'Борис', votes = 40 } }):build(db.dialect))
--> { affected = 2, last_id = 1 }
db:query(users:select('id', 'name'):where('votes', '>', 100):build(db.dialect))
--> { { id = 1, name = 'Анна' } }
db:query('select id, name, votes from users where id = ?', { n = 1, 2 })
--> { { id = 2, name = 'Борис', votes = 40 } }
db:execute('update users set votes = votes + ? where id = ?', { n = 2, 1, 2 })
--> { affected = 1, last_id = 0 }
```

Соединение открывается первым вызовом, а не в `mysql.new`: драйвер заводят
при подъёме узла, когда ходить к чужой службе рано.

| Вызов | Что делает |
|---|---|
| `db:query(sql, params, opts)` | выборка: массив записей по именам столбцов; NULL — отсутствующий ключ |
| `db:execute(sql, params, opts)` | оператор без выборки: `{ affected = n, last_id = id }` |
| `db:transaction(fn, opts)` | транзакция на одном соединении (ниже, «Транзакции») |
| `db:stats()` | показатели пула без учётных данных |
| `db:close()` | закрывает драйвер (ниже, «Соединения») |

`opts` у `query` и `execute` — `{ timeout, idempotent, max_rows }`: срок
вызова, согласие на повтор после отправки (ниже, «Повторы») и предел
строк. `last_id` — ключ `AUTO_INCREMENT`, который завёл **этот** оператор
(у вставки нескольких строк — первый), `0` — оператор ключа не заводил.
Это `mysql_insert_id`, а не `last_insert_id()`: тот помнит ключ прошлой
вставки сеанса и соврал бы после `update`.

Поля драйвера: `db.dialect` — правила диалекта `mysql` для `tnt-sql`,
`db.features.transaction` — `true`, `db.name` — имя драйвера.

### Настройки

| Ключ | Что | По умолчанию |
|---|---|---|
| `host`, `port` | узел | `127.0.0.1`, `3306` |
| `user`, `db` | учётная запись и база — **обязательны** | — |
| `password` | пароль | без пароля |
| `tls` | `{ ca, cert, key }` — TLS со сверкой сертификата сервера по корню `ca`; `true` — исключение (ниже, «Шифрование и ключ сервера») | открытый текст |
| `server_public_key` | файл открытого ключа RSA сервера: им полный вход без TLS шифрует пароль | ключ присылает сервер |
| `timeout`, `max_timeout` | срок вызова и его потолок, секунд; потолок — ещё и `max_execution_time` выборки на сервере | `5`, `60` |
| `max_rows` | предел строк выборки | `10000` |
| `pool` | `size`, `wait_timeout`, `idle_timeout`, `max_lifetime`, `open_cooldown`, `leak_timeout`, `sweep_interval` — как у `tnt-pool` | умолчания `tnt-pool` |
| `retry` | `attempts`, `base`, `factor`, `jitter`, `max` — как у `tnt-retry` | умолчания `tnt-retry` |
| `name` | имя в журнале, в пуле и в ведре повторов | `mysql` |

Набор ключей у драйверов над роком общий (`tnt.storage.driver`), свой
у MySQL — только `server_public_key`. Проверяется всё сразу
в `mysql.new`, и негодное — исключение на строке того, кто завёл драйвер:

```lua
mysql.new({ user = 'app', db = 'app', pasword = 'x' })
--> исключение: настройки mysql: ключа «pasword» нет, есть db, host, max_rows,
--  max_timeout, name, password, pool, port, retry, server_public_key, timeout, tls, user
```

Строки соединения нет: рок передаёт узел, учётную запись, пароль и базу
коннектору отдельными аргументами, и пароль стенда `app'se\cret` входит
как есть, без экранирования.

### Вход и значения

Драйвер принимает **пару `sql, params`** и текст не собирает, не разбирает
и не правит. `params` — массив с полем `n`, чтобы `nil` посреди
не терялся; без `n` — исключение: рок принял бы таблицу одним значением
и молча записал бы NULL.

Пару собирает `tnt-sql`: `build(db.dialect)` ставит знаки `?`, значения
кодирует `tnt-storage` (`value.wire`). Текст руками — тоже пара: знаки `?`,
значения — массивом после текста. Драйвер кодирует их тем же `value.wire`:
`int64`, `decimal`, `uuid` уходят строкой без потерь, время — мигом в UTC
(`DATETIME` пояса не хранит), `storage.json` — текстом JSON,
`storage.binary` — байтами. Без параметров рок идёт простым путём,
с параметрами — подготовленным на сервере; выдача у путей одна.

```lua
local storage = require('tnt.storage')

db:query('select ? as a, ? as b, ? as c', { n = 3, 'x', nil, 3 })
--> { { a = 'x', c = 3 } }
db:execute(users:insert({ name = 'Вера', meta = storage.json({ tags = { 'a' } }) }):build(db.dialect))
--> { affected = 1, last_id = 3 }
db:query('select id from users where id = ?', { n = 1, 3LL })
--> { { id = 3 } }
```

Выборку драйвер к типам не приводит: рок не отдаёт фасаду типов столбцов,
а угадывать тип по значению — портить строки, похожие на числа.

| Столбец | Что отдаёт рок | Как брать точно |
|---|---|---|
| NULL | ключа нет | — |
| `INT`, `DOUBLE`, `TINYINT(1)` | число | — |
| `BIGINT` | число до 2⁵³, дальше `int64` | — |
| `BIGINT UNSIGNED` | число до 2⁵³, дальше `uint64` — точно и за 2⁶³ | — |
| `DECIMAL` | строка точно | `decimal.new` |
| даты и время | строка | `datetime.parse` знающим пояс |
| `JSON` | строка | `json.decode` |
| `BLOB` | байты | `storage.decode_binary('mysql', v)` |

```lua
db:query('select cast(1.10 as decimal(10, 2)) as num, 1.5e0 as dbl')
--> { { num = '1.10', dbl = 1.5 } }
db:query('select meta from users where id = 3')
--> { { meta = '{"tags": ["a"]}' } }
```

**Один оператор на вызов.** Драйвер текст не разбирает и запрета
не проверяет: одиночный оператор гарантирует `tnt-sql` (`sql.raw`
отказывает на `;` вне кавычек), текст руками — пишущий. Форк хотя бы
не теряет отказ второго оператора, но первый к этому мигу уже выполнен.

### Отказ

Отказ — пара `nil, err`, где `err` — `TntStorageFailure` (раздел «Отказ»
документа `tnt-storage`): строкой, в JSON и в журнале — текст, а поля
говорят, что делать.

| Где | Род | `sent` | `retriable` | Соединение |
|---|---|---|---|---|
| соединение не открылось, вход не уложился в срок; сертификат сервера не прошёл сверку, нет файла корня или ключа сервера | `unreachable` | нет | да | не открыто |
| вход отвергнут: пароль, нет базы, нет прав, чужой закреплённый ключ (`1044`, `1045`, `1049`…) | `denied` | нет | нет | не открыто |
| соединения из пула за срок не досталось | `busy` | нет | да | — |
| ответа нет за срок вызова | `timeout` | да | с `idempotent` | выброшено |
| выборку снял `max_execution_time` сервера (`3024`) | `timeout` | да | с `idempotent` | в пул; в транзакции — `ROLLBACK` |
| срок вышел до вызова рока | `timeout` | нет | нет | в пул |
| соединение оборвалось: рок пометил его негодным, либо сервер закрыл сеанс (`2006`, `2013`, `1927`…) | `broken` | да | с `idempotent` | выброшено |
| сервер отказал оператору: синтаксис, ограничение, права, недостающий параметр (`2031`) | `rejected` | да | нет | в пул; в транзакции — `ROLLBACK` |
| взаимоблокировка, ожидание блокировки (`1213`, `1205`, `3572`) | `conflict` | да | нет — повторяют всю транзакцию | в пул; в транзакции — `ROLLBACK` |
| строк больше `max_rows` | `overflow` | да | нет | в пул |
| драйвер закрыт | `closed` | нет | нет | — |

Как род выбирается: сначала местная живость — `quote('')` рока бросил,
значит `broken`, что бы ни было в тексте. Жив — род решает **errno**,
который отдаёт форк (`server_code`), а без него (рок без починки) —
английские слова отказа. Перечень кодов и слов — в `tnt-storage`
(`tnt.storage.codes`), один на все драйверы. У отказа входа errno тоже
есть: неверный пароль (`1045`) от закрытого порта (`2002`) отличает код.

`message` — текст сервера, прошедший `tnt-log.scrub`. Отказ входа MySQL
кончается «(using password: YES)», и `scrub` принимает это за пару с тайной
и съедает хвост («(using password: [скрыто]») — тайны там нет, а смысл
пропадает. Фасад переводит скобку в слово **до** `scrub`: «(с паролем)»
или «(без пароля)»; общее правило `scrub` не тронуто.

```lua
db:execute('insert into users (id, name) values (?, ?)', { n = 2, 1, 'дубль' })
--> nil, Duplicate entry '1' for key 'users.PRIMARY'
--      (kind = rejected, sent = true, retriable = false, server_code = 1062)
db:query('selec 1')
--> nil, You have an error in your SQL syntax; … near 'selec 1' at line 1
--      (kind = rejected, sent = true, retriable = false, server_code = 1064)
mysql.new({ port = 13306, user = 'app', password = 'wrong', db = 'app' }):query('select 1')
--> nil, mysql 127.0.0.1:13306/app: вход не удался: Access denied for user 'app'@'172.17.0.1' (с паролем)
--      (kind = denied, sent = false, retriable = false, server_code = 1045)
mysql.new({ port = 1, user = 'app', db = 'app', pool = { wait_timeout = 0.1 }, retry = { attempts = 1 } }):query('select 1')
--> nil, соединение не получено за 0.1 с: открыть соединение не удалось: mysql 127.0.0.1:1/app: вход не удался:
--      Can't connect to server on '127.0.0.1' (2)
--      (kind = unreachable, sent = false, retriable = true)
```

Число в скобках у отказа сети — код ошибки системы, который коннектор
прочёл в миг отказа: от системы и даже от процесса он зависит — в свежем
процессе на Linux там `(115)`.

Исключение — только ошибка программиста: `sql` не строка, `params` без `n`,
значение, которое нельзя передать (таблица без `storage.json`), незнакомый
ключ настроек, `tls` без корня, `tls` или `server_public_key` на роке без
заплаты 0011, срок ноль, бесконечность или длиннее потолка, и ошибки
транзакции ниже.

В HTTP отказ хранилища сам не переходит: у него нет `status`. Потребитель
переводит его в свой ответ сам: `unreachable`, `busy`, `timeout`, `broken`
— служба недоступна, `conflict` — свой код 409, если повтор бессмыслен.

### Срок

Один миг на вызов — `clock.monotonic() + timeout` на входе, — и перед
каждым ожиданием остаток считается заново от времени планировщика:
ожидание пула (не дольше `pool.wait_timeout`), вход, ответ, `ROLLBACK`,
пауза повтора. Срок вызова — `opts.timeout`, иначе `timeout` драйвера.

У рока срока нет ни на вход, ни на запрос, поэтому **ответ ждётся
в работнике** (`within.call` из `tnt-storage`): рок зовёт отдельный файбер,
вызывающий ждёт его итога с остатком срока, а не дождавшись — отменяет
работника, соединение выбрасывает и отдаёт `timeout`. Вход, завершившийся
после срока, закрывается там, где появился.

```lua
db:query('select sleep(2)', nil, { timeout = 0.2 })
--> nil, mysql 127.0.0.1:13306/app: ответа нет за 0.2 с
--      (kind = timeout, sent = true, retriable = false)
```

Брошенный запрос **дорабатывает на сервере**. Потолка на всякий оператор
у MySQL нет; есть `max_execution_time` — только для `SELECT`. Драйвер
ставит его сразу за входом, равным потолку `max_timeout`, и брошенную
выборку сервер снимает сам; прочие операторы дорабатывают до конца.
`SLEEP`, который этот срок рвёт молча и с успехом, до вызывающего дойти
не может: срок вызова не длиннее потолка и истекает раньше серверного.

```lua
db:query('select @@session.max_execution_time as ms')
--> { { ms = 60000 } }
```

### Повторы

Весь вызов идёт под `tnt-retry` со своим экземпляром на драйвер
(`scope` — имя драйвера), и повторяет он по полю `retriable` отказа:

- **до отправки — всегда**: соединение не открылось, пул занят;
- **после отправки — только с `idempotent = true`**: `timeout` и `broken`.
  Обрыв до отправки от обрыва после по тексту не отличить, а `select`
  бывает с последствиями (`for update`, функции), и драйвер текста
  не разбирает;
- **никогда**: `rejected`, `denied`, `conflict`, `overflow`, `closed`.

Срок, вышедший до очередной попытки, отдаёт отказ прошлой попытки без
повтора: пауза `tnt-retry` меряет свой срок от своего начала и может
в него уложиться, не уложившись в миг вызова. Повтор пишется в журнал
`debug` самим `tnt-retry`.

### Транзакции

`db:transaction(fn, opts)` берёт одно соединение, шлёт `BEGIN` и зовёт
`fn(tx)`; у `tx` те же `query` и `execute`.

```lua
db:transaction(function(tx)
    local _, err = tx:execute('update users set votes = votes - 10 where id = ?', { n = 1, 1 })

    if err ~= nil then
        return nil, err
    end

    local _, err2 = tx:execute('update users set votes = votes + 10 where id = ?', { n = 1, 2 })

    if err2 ~= nil then
        return nil, err2
    end
end)
--> true

db:transaction(function(tx)
    tx:execute('delete from users')

    return nil, 'передумали'
end)
--> nil, передумали    (ROLLBACK: строки на месте)

db:transaction(function(tx)
    local rows = tx:query('select count(*) as n from users')

    return rows[1].n
end)
--> 3

db:transaction(function(tx)
    tx:execute('insert into users (id) values (1)')

    return tx:query('select 1 as one')
end)
--> nil, Duplicate entry '1' for key 'users.PRIMARY'
--      (kind = rejected, server_code = 1062)
```

- Тело ничего не вернуло — `COMMIT` и `true`, как у `box.atomic`. Первое
  значение `nil` или `false` — `ROLLBACK` и пара: `err` тела отдаётся как
  есть, без него — `rejected` «тело отменило транзакцию». Иное — `COMMIT`
  и это значение; отказ `COMMIT` — пара и `ROLLBACK`.
- **Первый отказ оператора помечает транзакцию**: следующие операторы `tx`
  сразу отдают тот же отказ (`retriable = false`), фиксации не будет —
  `ROLLBACK` и пара, даже если тело вернуло значение. У MySQL транзакция
  после ошибки цела, а после взаимоблокировки сервер откатывает её сам —
  и следующий оператор пошёл бы уже без транзакции; поэтому фасад дальше
  не шлёт ничего.
- **Исключение в теле** — соединение выбрасывается (закрытие сокета
  откатывает транзакцию на сервере), исключение идёт дальше: это ошибка
  программиста.
- Оператор тела, не дождавшийся ответа, помечает соединение к выбросу:
  оно выбрасывается **без `ROLLBACK`** — в сокете недочитанный ответ.
- Взятие соединения и `BEGIN` повторяются по «Повторам»; операторы тела —
  никогда, и срока своего у них нет: срок один на транзакцию
  (`opts.timeout`), а у `tx:query`, `tx:execute` из настроек — только
  `max_rows`.
- `opts.retry = true` повторяет **всю транзакцию с телом**, если она
  кончилась конфликтом (`conflict`: взаимоблокировка, ожидание
  блокировки), — сервер откатил её сам. Тело обязано быть безопасным
  для повтора: всё, что оно делает мимо `tx`, случится дважды.
- Ошибки программиста — исключения: `tx` вне тела, `timeout`
  и `idempotent` у оператора `tx`, вложенная транзакция в том же файбере,
  транзакция внутри транзакции box.

```lua
db:transaction(function(tx)
    return tx:query('select 1', nil, { timeout = 1 })
end)
--> исключение: у оператора транзакции нет своего срока и повтора: их задаёт transaction
```

**Открыта ли транзакция, рок не говорит**, и `information_schema`
этого без права `PROCESS` не покажет. Состояние ведёт фасад: его `BEGIN`
ставит отметку на соединении, `COMMIT` и `ROLLBACK` снимают, и по ней
решается, откатывать ли перед возвратом. Поэтому **`BEGIN` текстом через
`db:execute` — ошибка программиста, которую драйвер не увидит**: соединение
уйдёт в пул с открытой транзакцией, и следующий взявший зафиксирует чужую
работу. Ловить её нечем: рок об открытой транзакции молчит. Точек
сохранения и курсора в договоре нет.

### Соединения

- **Пул — `tnt-pool`**, заведённый драйвером; соединения открываются
  лениво, одно соединение — один оператор за раз.
- **Живость — без сети**: `quote('')` рока экранирует на клиенте
  и бросает, только если рок сам пометил соединение негодным. Сетевой
  `ping()` удвоил бы обращения и на молчащем сервере повис бы без срока.
  Соединение, закрытое сервером в простое, так не видно: его узнаёт первый
  запрос родом `broken`, и тот повторяется, только если `idempotent`.
- **Сброс перед возвратом — без сети**: у крюка `reset` нет срока вызова.
  Соединение, которое вернулось с отметкой открытой транзакции (след
  ошибки фасада), выбрасывается с записью `warn`. Отказ сервера посреди
  транзакции фасад откатывает сам — `ROLLBACK` в остаток срока, до
  возврата, — не вышло — выбрасывает.
- **Выброс, пока работник внутри рока**, закрывает выход работника, а место
  в пуле освобождается сразу: `close()` рока ждёт замка соединения, и
  выбросивший ждал бы вместе с ним.
- **Отмена вызывающего** выбрасывает соединение и уходит дальше тем же
  исключением отмены, а не парой.
- **Закрытие** закрывает пул: свободные соединения — сразу, занятые — когда
  их вернут. Повторное закрытие и вызов после — пара `closed`.

```lua
db:close()
--> true
db:close()
--> false, mysql: драйвер уже закрыт    (kind = closed)
db:query('select 1')
--> nil, mysql: драйвер закрыт    (kind = closed)
```

### Журнал

| Событие | Уровень | Поля | Кто пишет |
|---|---|---|---|
| соединение выброшено | `warn` | `driver`, `kind`, `reason`; после исключения в теле транзакции — `reason` об этом | драйвер |
| соединение вернулось с открытой транзакцией | `warn` | `driver` | драйвер, крюк `reset` |
| соединение не открылось | `warn` | `pool`, `err`, `streak` | `tnt-pool` |
| повтор | `debug` | `attempt`, `delay`, `err` | `tnt-retry` |

Ни текста запроса, ни значений параметров в журнале нет: в тексте руками
бывают литералы с тайнами. Пароль живёт только в настройках внутри
замыкания входа: ни `stats()`, ни текст отказа его не показывают.

```lua
db:stats()
--> { name = 'mysql', size = 4, busy = 0, idle = 0, total = 0, opened = 2, takes = 21,
--    gives = 19, drops = 2, discarded = 2, open_failures = 0, waiting = 0, waits = 0,
--    wait_timeouts = 0, leaks = 0, closed = true }
```

### Шифрование и ключ сервера

Против посредника в сети у драйвера два средства, и оба рок берёт
с заплатой 0011:

| Настройка | Что даёт | Опция коннектора |
|---|---|---|
| без `tls` | открытый текст | — |
| `tls.ca` | TLS: сертификат сервера сверяется по корню из файла, имя узла — по сертификату | `MYSQL_OPT_SSL_CA`, `MYSQL_OPT_SSL_VERIFY_SERVER_CERT` |
| `tls.cert`, `tls.key` | сертификат клиента и его ключ; один из двух — файл, где лежат оба | `MYSQL_OPT_SSL_CERT`, `MYSQL_OPT_SSL_KEY` |
| `server_public_key` | файл открытого ключа RSA сервера: им полный вход без TLS шифрует пароль | `MYSQL_SERVER_PUBLIC_KEY` |

**TLS — только со сверкой сертификата, и корень обязателен.** Коннектор
без сверки на сервере без TLS — или за посредником, вычеркнувшим TLS
из приветствия, — молча идёт открытым текстом и при этом считает
соединение защищённым: `caching_sha2_password` шлёт пароль как есть.
Без корня неудачная сверка вход не обрывает: коннектор продолжает его
сверкой по хешу пароля, которую подписывают только серверы MariaDB
11.4 и новее, и сервер, выбравший `mysql_native_password`, успевает
получить ответ на пароль. Поэтому режима без сверки нет, `tls = true` —
исключение, а сервер без TLS отвергается словами «SSL is required, but
the server does not support it». Корни системы — тоже корень:
`tls = { ca = '/etc/ssl/certs/ca-certificates.crt' }`.

Имя узла коннектор сверяет с сертификатом везде, кроме `127.0.0.1`
и `::1`. Сертификат, который MySQL выпускает себе сам, имени узла
не несёт, и узлу по сети серверу нужен свой — такой выпускает стенд
(`test/stand/mysql.sh`).

```lua
local secured = mysql.new({
    port = 13306,
    user = 'app',
    password = "app'se\\cret",
    db = 'app',
    tls = { ca = '/tmp/tnt-stand/tnt-stand-mysql/ca.pem' },
})

secured:query("show session status where Variable_name in ('Ssl_version', 'Ssl_cipher')")
--> { { Variable_name = 'Ssl_cipher', Value = 'TLS_AES_256_GCM_SHA384' },
--    { Variable_name = 'Ssl_version', Value = 'TLSv1.3' } }
mysql.new({ user = 'app', db = 'app', tls = true })
--> исключение: настройки mysql.tls: нужен файл корня, которым подписан сертификат сервера, —
--  tls = { ca = 'ca.pem' }, docs/mysql.md
```

Сертификат сервера корнем не подписан или файла корня нет — отказ
`unreachable`, и повторяется он до срока: коннектор отдаёт его кодом
2026, тем же, что и обрыв посреди рукопожатия TLS.

```lua
mysql.new({
    port = 13306,
    user = 'app',
    password = "app'se\\cret",
    db = 'app',
    tls = { ca = 'other-ca.pem' },   -- корень, которым сертификат сервера не подписан
    pool = { wait_timeout = 0.5 },
    retry = { attempts = 1 },
}):query('select 1')
--> nil, соединение не получено за 0.5 с: открыть соединение не удалось: mysql 127.0.0.1:13306/app: вход не удался:
--      TLS/SSL error: self-signed certificate in certificate chain
--      (kind = unreachable, sent = false, retriable = true)
```

**Закреплённый ключ сервера** — для входа без TLS. Полный вход
`caching_sha2_password` шифрует пароль открытым ключом RSA сервера
(выше, «Сервер — MySQL 8.4 или 9»). С `server_public_key` ключ
берётся из файла, а не от сервера по тому же соединению, и посредник
с подменённым ключом пароля не прочтёт. Ключ лежит в каталоге данных
MySQL (`public_key.pem`), его же отдаёт запрос `show status like
'Caching_sha2_password_rsa_public_key'` — по каналу, которому доверяют.
С `tls` ключ не нужен: пароль идёт внутри TLS.

Файл ключа, который не прочесть, — отказ до входа: коннектор без файла
спросил бы ключ у сервера по тому же соединению — ровно то, от чего ключ
закрепляют. Файл, который прочитан, но не ключ, коннектор отвергает
во входе без слов — «Unknown or undefined error code (2000)», родом
`unreachable`. Чужой ключ сервер не расшифрует и откажет во входе,
а хеша пароля после отказа не запомнит.

```lua
-- свежая учётка: хеша её пароля в кэше сервера нет, и вход — полный
local root = mysql.new({ port = 13306, user = 'root', password = 'root-secret', db = 'app' })

root:execute("create user 'fresh'@'%' identified with caching_sha2_password by 'fresh-secret'")
root:execute("grant select on app.* to 'fresh'@'%'")

mysql.new({ port = 13306, user = 'fresh', password = 'fresh-secret', db = 'app', server_public_key = 'other.pub' })
    :query('select 1')
--> nil, mysql 127.0.0.1:13306/app: вход не удался: Access denied for user 'fresh'@'172.17.0.1' (с паролем)
--      (kind = denied, sent = false, retriable = false, server_code = 1045)
mysql.new({
    port = 13306,
    user = 'fresh',
    password = 'fresh-secret',
    db = 'app',
    server_public_key = 'absent.pub',
    pool = { wait_timeout = 0.5 },
    retry = { attempts = 1 },
}):query('select 1')
--> nil, соединение не получено за 0.5 с: открыть соединение не удалось: mysql 127.0.0.1:13306/app: вход не удался:
--      Can't read the server public key file 'absent.pub': No such file or directory
--      (kind = unreachable, sent = false, retriable = true)

local pinned = mysql.new({
    port = 13306,
    user = 'fresh',
    password = 'fresh-secret',
    db = 'app',
    server_public_key = '/tmp/tnt-stand/tnt-stand-mysql/public_key.pem',
})

pinned:query("show session status like 'Ssl_cipher'")
--> { { Variable_name = 'Ssl_cipher', Value = '' } }    — без TLS, пароль ушёл закреплённым ключом
```

Ключ бережёт пароль, но не обмен: без `tls` запросы и ответы идут
открытым текстом. Рок без заплаты 0011 незнакомые ключи пропускает
молча и вошёл бы открытым текстом, поэтому `tls` и `server_public_key`
на нём — исключение при заведении:

```lua
mysql.new({ user = 'app', db = 'app', tls = { ca = 'ca.pem' } })   -- рок собран до заплаты 0011
--> исключение: настройки mysql.tls: рок mysql собран без заплаты rocks/mysql/0011 и молча пропустил бы её —
--  пересоберите: make deps-mysql, docs/mysql.md
```

### Подмена в проверках

Рок пакет берёт по имени через `tnt.storage.link`: загрузка рока —
внешняя зависимость `require`, объявленная `tnt-external`, и проверка
ставит на её место двойника, не трогая `package.loaded`.
`_set_source(nil)` возвращает настоящий рок.

```lua
local link = require('tnt.storage.link')

link._set_source({
    require = function()
        return nil, "module 'mysql' not found:"
    end,
})
mysql.new({ user = 'app', db = 'app' })
--> исключение: рок mysql не установлен (module 'mysql' not found:): поставьте форк с починками — make deps-mysql, docs/mysql.md
link._set_source(nil)
```

Двойник отвечает тем же договором, что форк: у него поле `features`
с `ssl` и `server_public_key`, а `connect(opts)` отдаёт
соединение с `execute(sql, ...)`, `quote(value)`, `close()` и полем
`conn` — объектом драйвера рока, чей `close()` закрывает и оборванное
соединение; `execute` отдаёт наборы записей, `true`, число строк и новый
ключ (`uint64`) либо бросает `box.error` с полем `mysql_errno`, а `quote`
и `close` бросают на негодном соединении.

## Чем пришлось поступиться

- **Файбер на каждый вызов рока.** Иначе срока нет вовсе; цена —
  порождение файбера и канала на вызов. Отменённая выборка дорабатывает
  на сервере до `max_execution_time`, прочие операторы — до конца.
- **`BEGIN` текстом не виден**: рок не говорит об открытой транзакции,
  и отметку ведёт только фасад.
- **Открытая транзакция при возврате — выброс, а не откат**: `reset` без
  сети откатить не может.
- **Лишний запрос на каждое новое соединение**: `SET SESSION
  max_execution_time` сразу за входом.
- **NULL — отсутствующий ключ**: запись не знает своих столбцов.
  Повторяющиеся имена столбцов схлопываются в последнее.
- **`max_rows` считается после чтения** — память уже потрачена.
- **Один оператор на вызов драйвер не проверяет** — только `tnt-sql`.
- **Рок — форк**, а не выпуск: заплаты живут в `rocks/mysql/`
  и накладываются на закреплённый коммит; подъём коммита — отдельная
  правка со сверкой живыми проверками заново.
- **Без `tls` и `server_public_key` полный вход берёт ключ сервера
  по сети**, и посредник, подменивший ключ, прочтёт пароль: закрепляют
  ключ настройки, а не умолчание — файла ключа у драйвера нет, пока его
  не назвали.
- **TLS — только со сверкой по корню из настроек**: режима «шифровать,
  не сверяя» нет, и сертификат, который MySQL выпускает себе сам,
  по сети сверки имени узла не пройдёт — серверу нужен свой.
- **Отказ сверки сертификата — `unreachable`** и повторяется до срока:
  коннектор отдаёт его тем же кодом 2026, что и обрыв посреди
  рукопожатия TLS. Так же — нет файла корня или ключа сервера.
- **Рок тянет OpenSSL системы**: на нём и `caching_sha2_password`,
  и TLS коннектора.

## Проверки

Проверки лежат в `test/` и идут на luatest: `.rocks/bin/luatest test/`.

- `settings_test.lua`, `rock_test.lua`, `mysql_test.lua` — 24 проверки
  на двойнике рока: настройки, `tls` с корнем и его отказы, ключ сервера,
  вход аргументами с шифрованием и ключом, отказ рока без заплаты 0011
  на строке заведшего, потолок выборки, живость по `quote('')`, errno
  и слово о пароле, счёт числом,
  пока точен, фасад насквозь — диалект, пара от `tnt-sql`, род отказа
  по errno и словам, откат по отметке транзакции, отмена вызывающего:
  исключение отмены, а не пара, соединение выброшено, занятых в пуле
  нет. Пул, срок, повторы и транзакции как таковые проверяет
  `tnt-storage` своим двойником, один раз на все драйверы над роком.
- `fork_test.lua` — проверка сборки форка без стенда: из группы драйвера
  не видно ни функций коннектора, ни его zlib — `deflateReset` находится
  в системной libz, `mysql_real_connect` не находится вовсе, — а системная
  zlib рядом с драйвером сжимает и разжимает. Смотрит на символы, а не ждёт
  падения: там, где версии zlib совпали, падения нет, а сборка всё равно
  негодна. Идёт только на Linux.
- `mysql_live_test.lua` — 15 проверок против MySQL стенда с форком
  рока: типы туда и обратно, `affected` и `last_id`, значения после NULL,
  выдача подготовленного пути целиком — каждая строка, — число во всю
  длину столбца, `false` столбца `boolean` в 2000 чтениях, перед каждым
  из которых куча сдвинута и буфер ложится на новое место, отказ второго
  оператора, errno `1064`, `1062`, `2031`, `1044`, `1045` и слово
  о пароле, вход свежей учётки через
  `caching_sha2_password` — ключом RSA без TLS, затем по кэшу сервера, —
  TLS с корнем стенда (`Ssl_cipher` не пуст), отказ с чужим корнем
  и без файла корня, полный вход с закреплённым ключом стенда, отказ
  `1045` с чужим ключом и без файла ключа, срок после работы без уступки
  (`[0,29; 0,35]` с при сроке 0,3 с), потолок выборки, сеанс, убитый
  `KILL`, и его повтор с `idempotent`, взаимоблокировка `1213`. Проходят
  на MySQL 8.4.11 с настройками по умолчанию и на MySQL 9.7.2.

```sh
make deps-mysql                                  # форк рока в .rocks: CMake, компилятор и libssl-dev
make mysql-up                                    # MySQL 8.4: порт 13306, учётки app, reader и root, TLS
.rocks/bin/luatest test/mysql_live_test.lua
make mysql-down

# MySQL 9 — тем же сценарием стенда, рядом с 8.4
STAND_MYSQL_IMAGE=mysql:9 STAND_MYSQL_CONTAINER=tnt-stand-mysql-9 STAND_MYSQL_PORT=13319 make mysql-up
STAND_MYSQL_PORT=13319 .rocks/bin/luatest test/mysql_live_test.lua
STAND_MYSQL_CONTAINER=tnt-stand-mysql-9 make mysql-down
```

Без рока, на роке, собранном не по заплатам `rocks/mysql/`, или без
поднятого сервера живые проверки пропускаются: гейты не зависят ни
от докера, ни от сборки рока. Проверки шифрования и ключа пропускаются
ещё и тогда, когда ключа стенда нет в `/tmp/tnt-stand/<контейнер>`
(`MYSQL_TLS_DIR`) или сервер отдаёт другой — контейнер подняли прежним
сценарием, без сертификатов и ключа стенда. Проверка сборки форка стенда не ждёт
и пропускается только без рока или на роке не по заплатам. Покрытие
строк — 100 %, убитых мутантов — 100 %: `rock.lua` — 49,
`settings.lua` — 15; в `mysql.lua` мутировать нечего.
